# AionUi Linux release component

This component publishes the Linux AionUi identity `2.1.0-beta.editfork.21`. Its 548 static files and 83 WorkAgent builtin-assistant files remain byte-for-byte inputs from the read-only Windows `.20` migration reference after the complete 633-file checksum manifest and exact file set pass verification. The version increase is intentional: `.21` identifies the Linux fd3 possession-channel security contract and must never be represented as the older `.20` runtime.

Linux needs a native web host. `bin/aionui-web` is compiled from the separately pinned `.21` web-host compatibility source plus the checked-in WorkAgent fd3 runtime-auth and async-test-stability patch, using the verified Bun 1.3.14 Linux binary. The build reverses that patch with zero fuzz to the per-file base manifest, proves patch-created files are absent, reapplies it, and checks the exact post-state manifest before compilation. Its expected ELF hash is pinned and the build runs twice independently during qualification. `bin/package.json` is a separately checked `.21` Linux manifest, so `aionui-web version` cannot misidentify this protocol as `.20`.

In WorkAgent mode, bootstrap requires the exact non-secret pair `WORKAGENT_TENANT_ID` and `WORKAGENT_RUNTIME_FD=3`. The 32-byte random credential is never placed in an environment, argument or filesystem object: UserHost sends one fixed 42-byte `WATOKN1` record over an inherited anonymous Linux `AF_UNIX/SOCK_SEQPACKET`, then shuts down and closes its endpoint. AionUi validates fd type and `SO_PEERCRED`, bounds blocking reads, requires one exact record followed by peer shutdown, closes fd3, and creates a fresh equivalent channel for every AionCore Start attempt. Partial/malformed markers, the removed `WORKAGENT_RUNTIME_TOKEN` environment name, and local-backend combinations fail before listeners start. Static content, feedback, API, WebSocket and STT routes require exactly one canonical `X-WorkAgent-Runtime-Token`; browser-supplied `X-WorkAgent-*` headers are stripped before trusted reinjection, while AionCore JWT/session authorization remains in force. Standalone AionUi does not inspect or close fd3 when both markers are absent, even if an unrelated readable socket occupies that descriptor.

Run `scripts/build-aionui-linux.sh`. It is offline, refuses to overwrite an output, rejects source/reference symlinks or file-set drift, proves the reversible patch chain, runs the complete AionUi Vitest set (with its process-global-storage and fixed-timeout DOM cases isolated), the package-local start tests, and a real Bun fd3 process test, type-checks both web packages, checks formatting, normalizes immutable-ready modes, and writes the artifact to `.tools/artifacts/aionui-2.1.0-beta.editfork.21-linux-x64` by default. Its release-root payload is:

- `bin/aionui-web` and `bin/package.json`;
- `static/` copied byte-for-byte from Windows production;
- `workagent-builtin-assistants/` copied byte-for-byte from Windows production;
- audit material under `share/workagent-components/aionui/`.

The root-only combined-runtime gate is `WORKAGENT_RUNTIME_AUTH_RUNTIME_ROOT=/absolute/release/root go test ./internal/userhost -run TestRealRuntimeAuthRejectsCrossUIDDirectAccess -v`. It does not install or start a service: it launches the real release binaries transiently, proves the secret is absent from both child environments and argument vectors, requires AionUi's exact non-secret markers in its initial `/proc` environment, requires AionCore to have byte-scrubbed the tenant, fd and removed legacy-token entries from its initial `/proc` environment, and exercises the second-UID 403 and JWT non-bypass contract. The ordinary source gate also runs a live same-UID sibling attack under `kernel.yama.ptrace_scope=2`, requiring procfs socket open to fail with `ENXIO` and `pidfd_getfd` to fail with `EPERM`.

The AionUi source `LICENSE` is copied into that audit directory only after its pinned checksum passes. Bundling this original file is distribution evidence, not a substitute for the project-wide approved license report.

The project-wide release assembler must merge this payload with AionCore and the three Agent CLIs, then produce the signed manifest, SBOM, provenance and approved license report. No user database, OAuth token, browser state or credential is an input.
