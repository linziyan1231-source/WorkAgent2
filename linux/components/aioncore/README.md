# AionCore Linux compatibility component

This is the explicitly versioned Linux production-compatibility release AionCore `v0.1.42-editfork.15`, selectively synchronized from Windows `.14` source plus its recorded read-only working snapshot. It is not described as a reproducible copy of that dirty snapshot. The complete 1,399-file Linux source snapshot (including modes and paths) is pinned by a canonical source-tree tar hash, while `Cargo.lock`, Rust 1.95.0, the source-bound test attestation, and the final release ELF are pinned independently.

The snapshot adds a single fresh-process retry after ACP initialize timeout, resumable 1 GiB uploads (16 MiB chunks, three concurrent transfers and 24-hour sessions), and the `workagent-help` skill referenced by the current built-in WorkAgent assistant. It preserves the WorkAgent fd3 socket transport boundary, Linux possession-only keyring delivery for cron helpers, bundled AionRS runtime, task and cron safety fixes, cross-platform inbound filename-separator handling, and reproducible `SOURCE_DATE_EPOCH` behavior.

`scripts/build-aioncore-linux.sh` copies the verified source to a locked canonical build path, disables Cargo networking, forces the pinned epoch in `SOURCE-DATE-EPOCH`, remaps source/target/Cargo/Rust paths to stable virtual prefixes, requests and verifies the pinned SHA-1 linker build ID, and runs formatting, strict workspace clippy, a focused channel regression, and a clean locked release build. It either runs the complete workspace suite or strictly verifies the byte-pinned `TEST-ATTESTATION.json` for this exact source tree; an arbitrary or stale attestation fails closed. It rejects leaked physical build paths before packaging and adds a fully pinned Linux managed-resource directory containing Node 24.11.0, patched `@agentclientprotocol/codex-acp` 1.1.2 with managed Codex 0.144.4, and Claude Agent ACP 0.39.0. AionCore retains the historical `0.16.0-aion-fork-steer.6` directory as a compatibility slot only; the manifest and runtime checks reject the deprecated `@zed-industries/codex-acp` implementation.

The payload places `aioncore` at `bin/aioncore` and its managed resources at `bin/managed-resources`, matching AionCore's executable-relative resolver. All release entries must be real files or directories; source archive and npm symlinks are normalized during approved material preparation and are rejected by the final package. The source-tree `LICENSE` is copied byte-for-byte after its dedicated checksum passes. Audit inputs live under `share/workagent-components/aioncore/`.

The build performs version/help checks, exact package/patch/license gates, a real ACP stdin/stdout fork/steer route test, and a bundled-resource activation smoke test before writing an immutable-ready output under `.tools/artifacts/`. `MANAGED-COMPONENTS.json` and the retained package locks provide the nested reviewer inventory. The exact `.29` frontend and WorkAgent assistants are supplied by the separate AionUi component.
